# SIDE_QUEST_template

> The light build shape — four docs and nothing else. For work that needs the Director→CLIde cycle but not a project's apparatus: experiments, probes, one-off tools, and the tutorial build. Copied, never filled in here.

| Rule                                                                                                              |
| ------------------------------------------------------------------------------------------------------------------- |
| Copy this folder into `../../PROJECTS/ACTIVE/` as `[name]/` — active work lives in ACTIVE whatever its shape       |
| It rests in `../../PROJECTS/SIDE_QUESTS/` when nobody is working it, and moves back to ACTIVE when they are        |
| The four docs are the whole shape: the prompt, the report, CLIde's card, and a scratchpad                          |
| No STATE, no PRD, no parking lots, no CODEBASE maps — a quest that starts needing them has become a project, so copy `../PROJECT_template/` in and graduate it |
| The `BUILD/` path matters: CLIde resolves `PROJECTS/ACTIVE/[NAME]/BUILD/ACTION_PROMPT.md` and finds nothing anywhere else |

## Dive Card

> Guide: not a walk stop — deliver the fenced block verbatim only when the user takes the dive option at the shelf fork.

```
── Tour Stop — TEMPLATES/SIDE_QUEST_template/

The small version of a project. Four documents: the instruction going
out, the report coming back, the builder's memory card, and a
scratchpad for everything that isn't either.

It exists because the full project shape is too much furniture for
some work. An afternoon experiment does not need a requirements
document or a parking lot for future features — it needs somewhere
the two seats can pass work back and forth, and somewhere to think.

Copied into your active projects when the work is live, moved to the
side quests folder when it goes quiet. If one turns out to matter,
the full project shape gets copied in around it and it graduates.
```
